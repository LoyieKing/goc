# test/

Everything that checks goc lives here; product code does not.
`scripts/ci-test.sh` runs the runners below in CI order. Every runner
sources `test/lib.sh`, which rebuilds `bin/goc` and takes the tool paths
from `goc env`.

| Path | What it checks | Runner |
|------|----------------|--------|
| `clang/` | Clang Sema for the pointer colors (patched clang) | `test/clang/run.sh` |
| `color-escape/` | the `goc-color-escape` pass (via `color-escape.sh`, opt + plugin) on C inputs: expected colors, errors, uptr round-trips, the color report (`EXPECTATIONS` lists the cases) | `test/color-escape/run.sh` |
| `lit/` | FileCheck tests of the IR passes and goc-llc on `.ll` inputs | `test/lit/run.sh` (needs `lit`) |
| `gocobj/` | `.gocobj` format goldens and verify negatives (`v1.0/`, regenerated by `gen/`) | `go test ./internal/gocobj/` |
| `e2e/` | C through `bin/goc` into Go programs that run: one file at -O0 (`realbody`), reproducible builds (`repro`), Go → C ABIInternal thunks (`goabi`), C → Go stubs (`go_extern`), all stack-check tiers under moving stacks (`stress`), returned stack pointers (`retptr`), 600 functions (`manyfuncs`), C lines in Go tracebacks (`lines`), and linux/arm64 under qemu-aarch64 (`arm64/run.sh` and the `arm64-*` cases) | `test/e2e/run.sh [case...]` |
| `e2e/qjs/` | QuickJS on goroutine stacks: `host/` (C host and libc shim compiled by goc), `embed/` and `cli/` (the Go programs), and the test262 / official-test / CLI runners | `scripts/qjs-cli-build.sh`, then `test262-sample.py`, `official-tests.py`, `cli-tests.sh` |

Go unit tests sit next to their packages under `internal/`, as Go requires. Build output goes to `build/test/`.
Benchmarks are in `bench/`, not here.
