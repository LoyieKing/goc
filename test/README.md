# test/

Everything that checks goc lives here; product code does not. Each
directory has a `run.sh`; `scripts/ci-test.sh` runs them in CI order.

| Path | What it checks | Runner |
|------|----------------|--------|
| `clang/` | Clang Sema for the pointer colors: patched clang and the out-of-tree plugin (`clang/plugin`) | `test/clang/run.sh` (`goc test`, `goc test --plugin`) |
| `color-escape/` | the `goc-color-escape` pass (via `color-escape.sh`, opt + plugin) on C inputs: expected colors, errors, uptr round-trips, the color report (`EXPECTATIONS` lists the cases) | `test/color-escape/run.sh` |
| `lit/` | FileCheck tests of the IR passes and goc-llc on `.ll` inputs | `test/lit/run.sh` (needs `lit`) |
| `gocobj/` | `.gocobj` format goldens and verify negatives (`v1.0/`, regenerated by `gen/`), plus `verify-real.sh` for every object a build wrote | `go test ./gocobj/` |
| `e2e/realbody/` | One C file through the whole pipeline into a Go object | `run.sh` |
| `e2e/repro/` | Reproducible builds: one C file built twice gives identical `.gocobj`/`.goobj`, and converting a `.gocobj` 10 times gives one Go object | `run.sh` |
| `e2e/goabi/` | Go → C calls through the ABIInternal thunks (scalars, aggregates, stack arguments) | `run.sh` |
| `e2e/stress/` | C recursion in all stack-check tiers while GCs grow and shrink goroutine stacks | `run.sh` |
| `e2e/lines/` | C file/line numbers in Go tracebacks (`runtime.CallersFrames`), inlined frames | `run.sh` |
| `e2e/arm64/` | linux/arm64 under qemu-aarch64: the corpus in `run.sh`, stress and C stack arguments in `stress.sh` | `run.sh`, `stress.sh` |
| `e2e/qjs/` | QuickJS on goroutine stacks: `host/` (C host and libc shim compiled by goc), `embed/` and `cli/` (the Go programs), and the test262 / official-test / CLI runners | `scripts/qjs-cli-build.sh`, then `test262-sample.py`, `official-tests.py`, `cli-tests.sh` |

Go unit tests sit next to their packages (`gocobj/`, `goobj/lower/`,
`tools/gocobj2goobj/`), as Go requires. Build output goes to `build/test/`.
Benchmarks are in `bench/`, not here.
