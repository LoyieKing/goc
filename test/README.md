# test/

Everything that checks goc lives here; product code does not.
`scripts/ci-test.sh` runs the runners below in CI order. Every runner
sources `test/lib.sh`, which rebuilds `bin/goc` and takes the tool paths
from `goc env`.

| Path | What it checks | Runner |
|------|----------------|--------|
| `lit/` | lit/FileCheck: the patched clang's Sema for the pointer colors (`Sema/`), the `goc-color-escape` pass on C and IR inputs including uptr round-trip executables and the color report (`ColorEscape/`), stack maps (`StackMap/`), goc-llc (`CodeGen/`) | `test/lit/run.sh` (needs `lit`) |
| `gocobj/` | `.gocobj` format goldens and verify negatives (`v1.0/`, regenerated by `gen/`) | `go test ./internal/gocobj/` |
| `e2e/` | C through `bin/goc` into Go programs that run: one file at -O0 (`realbody`), reproducible builds (`repro`), Go → C ABIInternal thunks (`goabi`), C → Go stubs (`go_extern`), all stack-check tiers under moving stacks (`stress`), returned stack pointers (`retptr`), 600 functions (`manyfuncs`), C lines in Go tracebacks (`lines`), and linux/arm64 under qemu-aarch64 (`arm64/run.sh`, `arm64-stackargs/` and the `arm64-*` cases) | `test/e2e/run.sh [case...]` |

Go unit tests sit next to their packages under `internal/`, as Go requires. Build output goes to `build/test/`.
QuickJS, the real C program goc is checked on, is a port in `ports/quickjs/`
(see its README). Benchmarks are in `bench/`.
